# Portfolio Revamp System

## Objective

Transform this portfolio into a high-impact, recruiter-focused website that clearly demonstrates:

- Improve clarity, performance, and hiring conversion
- Emphasize gameplay engineering expertise
- Systems design thinking
- Ensure code is production-quality, maintainable and performance aware

The site must answer within 30 seconds:

1. What has this engineer built?
2. What systems did they design?
3. What technical challenges did they solve?
4. Why should we hire them?

---

## Target Audience

- Game studios (EA, Ubisoft, indie studios)
- Hiring managers and technical leads
- Recruiters with limited technical depth

---

## Core Principles

### 1. Systems Over Features

Always highlight:

- Architecture decisions
- Trade-offs
- Constraints
- Scalability

Avoid:

- Generic feature descriptions
- Vague statements like “implemented gameplay”

---

### 2. Clarity > Cleverness

- Prioritize readability and scanability
- Use clear section hierarchy
- Avoid visual clutter

---

### 3. Show Engineering Depth

Each project must communicate:

- Problem → Approach → Implementation → Result

---

### 4. Performance Matters

- Optimize load time
- Avoid unnecessary frameworks
- Lazy load heavy assets (e.g., Unity WebGL)

---

### 5. Modular Codebase

- Components must be reusable
- Avoid tight coupling
- Favor composition over inheritance

---

## Tech Direction

Preferred stack:

- Frontend: React
- Styling: Tailwind
- Hosting: Github.io
- Minimal dependencies

---

## Constraints

- Keep components modular and reusable
- Avoid unnecessary dependencies
- Prefer readability over cleverness
- Optimize for fast load times

---

## UX Requirements

- Recruiter can scan homepage in < 10 seconds
- Each project visible without scrolling too much
- Strong visual hierarchy
- Mobile responsive

---

## Project Page Requirements

Each project must include:

### 1. Overview

Short, impactful summary

### 2. Key Systems

Bullet list of systems implemented

### 3. Technical Breakdown

- Architecture diagram or explanation
- Key challenges
- Solutions

### 4. Visual Proof

- Screenshots
- Interactive demos if possible

### 5. Outcome

- Performance improvements
- Player impact
- Measurable results (if available)

---

## Agent Operating Rules

- Always propose a plan before coding
- Break tasks into small, reviewable steps
- Do not overwrite large files without explanation
- Ask for clarification when requirements are ambiguous
- Prefer incremental improvements over rewrites

---

## Code Standards

- Functions < 50 lines when possible
- Components < 200 lines
- Strong typing (TypeScript preferred)
- Meaningful naming (no abbreviations)

---

## Anti-Patterns (Avoid)

- Overengineering simple UI
- Overuse of animations
- Generic portfolio templates
- Walls of text with no structure

---

## Success Criteria

The portfolio should:

- Differentiate from other Unity developers
- Clearly communicate engineering thinking
- Be fast, clean, and professional
